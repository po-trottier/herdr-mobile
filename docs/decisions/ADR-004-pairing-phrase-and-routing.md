# ADR-004: Six-word Diceware pairing phrase and opaque 128-bit routing handle

## Status

Accepted. Supersedes the numeric-code pairing model. Amended 2026-09-02 (the phrase lifetime in
the Decision section).

## Date

2026-08-24

## Context

The earlier design used two separate numeric codes:

1. An 8-digit numeric security code as the `Noise_XXpsk0` pre-shared key. `log2(10^8)` is
   approximately 26.6 bits of PSK entropy.
2. A 6-digit numeric session code as the relay path segment, from which `SHA256(code)` was derived
   as a session identifier. The relay broadcasted reconnect attempts to all connected hosts.

Two codes for one act (pairing) confused the user. The numeric PSK was weak: 26.6 bits is
exhaustible offline in seconds if an attacker records the Noise handshake. The numeric session path
leaked a guessable routing space: an attacker who guessed a 6-digit code could reach the relay's
routing table.

The 10-pool prefix routing scheme and the reconnect broadcast added relay complexity for a weak
namespace.

## Decision

Replace both numeric codes with two orthogonal values that serve different purposes:

**Pairing secret:** six words selected uniformly with a cryptographic RNG from the EFF long
Diceware list (7776 entries). Word order is preserved. Canonical text is lowercase ASCII words
joined by single hyphens. Entropy is `log2(7776^6)`, approximately 77.5 bits. The canonical
hyphenated text becomes the `Noise_XXpsk0` pre-shared key by the derivation in
`docs/13-security-pairing.md` R-13-024, never as raw UTF-8 bytes. Lifetime is 120 seconds; at most
three handshake attempts per phrase.

Amendment, 2026-09-02: the phrase lifetime is 600 seconds, not 120 seconds, per
`docs/13-security-pairing.md` R-13-022 as amended that day. Under R-13-023 as amended that day,
the third failed attempt also destroys the phrase and the handle without minting a replacement;
the pairing pane waits for `p`. The rest of this decision stands.

**Routing handle:** 128 random bits generated by the Host, encoded as 22 unpadded base64url
characters. The handle is opaque: it carries no structure, no checksum and no embedded time. It is
not a bearer token — Noise authenticates both peers and protects all content. Knowing a handle lets
an attacker reach the relay's routing table and nothing else.

The two roles are split because a secret a human must type, speak aloud or read from a screen must
be memorable and typo-tolerant. A routing key a machine reads must be large enough that an attacker
cannot scan the namespace and opaque enough that it leaks no information. One value cannot satisfy
both constraints.

The Host generates both values and renders the QR code. The pairing URI carries the relay origin,
the handle and the phrase in one link, so the app needs no compiled default relay origin. The handle
survives reconnect and is destroyed on revoke, on unpair and when the operator origin changes.

The relay has no QR endpoint, no session-code path, no reconnect broadcast and no 10-pool prefix
routing. Pairing and reconnect use the same two paths: `/host/<handle>` and `/device/<handle>`.

The exact formats, validation errors, key-derivation rules and storage rules are owned by
`docs/13-security-pairing.md`. The wire protocol, close codes and one-active-Device enforcement are
owned by `docs/11-relay-protocol.md`. The UX for manual phrase entry is owned by
`docs/30-ux-spec.md`.

## Consequences

Easier: one secret replaces two codes. The user types or speaks six words once, not eight digits and
then six digits for two different purposes. The PSK has 77.5 bits of entropy instead of 26.6, which
moves it from trivially exhaustible to practically unbreakable offline. The 128-bit handle is not
guessable.

The relay becomes simpler: it holds one in-memory map (`handle -> connections`), serves two
well-known paths, and never broadcasts.

Harder: six words are longer to read aloud and longer to type than eight digits. Manual entry needs
autocomplete against the 7776-entry wordlist and a paste path for users who transfer the phrase by a
side channel. The UX cost is accepted and paid by the manual-entry rules in `docs/30-ux-spec.md`.

The wordlist URL is a remote dependency. The canonical URL
(`https://www.eff.org/files/2016/07/18/eff_large_wordlist.txt`) is an EFF resource that has been
stable since 2016. A local copy is not bundled; the Host fetches it once and caches it.
